# ANTIGRAVITY.md — полная инструкция: поставить скиллы и продолжить работу над Sad Launcher

Читай целиком, по порядку. После шагов 1–3 ты работаешь так же, как работал Claude Code: те же скиллы, тот же протокол, те же проверки.
Дата составления: 2026-11-17. Версия лаунчера: 0.7.0.

## 1. Установка (делается один раз, 2 минуты)

Все нужные скиллы уже лежат в проекте, в папке `antigravity/` (скачивать ничего не нужно):

| Папка | Что внутри |
|---|---|
| `antigravity/skills/` | 31 скилл + `allskill` (у каждого `SKILL.md`, часть с `reference/` и `scripts/`) |
| `antigravity/workflows/` | 9 команд: `tov`, `ui-audit`, `live`, `apple-hig`, `ecc-plan`, `ecc-tdd`, `ecc-code-review`, `ecc-verify`, `ecc-build-fix` |
| `antigravity/rules/allskill.md` | правило «всегда включено» — протокол на каждый ответ |
| `antigravity/setup-antigravity.ps1` | раскладывает всё по местам |

**Шаги**

1. Открой `D:\working WIN\LLM launcher` как рабочую папку в Antigravity.
2. В терминале из корня проекта выполни:
   ```powershell
   powershell -ExecutionPolicy Bypass -File antigravity\setup-antigravity.ps1
   ```
   Скрипт копирует папки в `.agent\skills|workflows|rules` и `.agents\skills|workflows|rules` (Antigravity читает одну из двух
   в зависимости от версии). Ключ `-Global` ещё кладёт скиллы в `%USERPROFILE%\.gemini\antigravity\skills`, чтобы они были видны
   в любом проекте.
3. Проверь, что IDE их увидела: Customizations (или Settings) → **Skills**, **Rules**, **Workflows**.
   В Rules должно быть `allskill` со значением Always On; в Skills — `allskill`, `impeccable`, `taste-skill` и остальные.
   Если пункт называется иначе или папки в твоей версии другие — смотри документацию Antigravity для своей версии и положи те же
   три папки туда, где IDE их ищет. Содержимое менять не нужно: формат (`SKILL.md` с `name` и `description`) стандартный.
4. Прочитай по порядку: `RRR.md` (вся история и грабли), `SKILLS.md` (каталог), `.agent/skills/allskill/SKILL.md` (протокол).
5. Выполни проверочный прогон, раздел 9. Только после него бери задачи.

Если нужны внешние ресурсы (Windows, Git Bash, Rust `x86_64-pc-windows-gnu`, Python 3 для одноразовых скриптов, `gh` для GitHub) —
они уже стоят на машине владельца.

## 2. Как «вызывать» скиллы в Antigravity (отличие от Claude Code)

В Claude Code был инструмент `Skill` и команды `/имя`. В Antigravity:

- **Скилл** = папка со `SKILL.md`. Подбирается по `description`, но не надейся на автоподбор: **сам открой `SKILL.md` и прочитай
  целиком**, затем выполни его инструкции. Ссылки `reference/...`, `scripts/...` внутри скилла открывай по мере надобности.
- **Workflow** (`/tov`, `/ui-audit`, `/live`, `/apple-hig`, `/ecc-*`) — это команды; запускаются через `/` в чате.
- Формулировки «вызови Skill X» в тексте скиллов читай как «прочитай `.agent/skills/X/SKILL.md` и следуй ему».
- Слова «Read/Write/Edit/Bash» в скиллах — это просто чтение/запись/правка файлов и терминал. Подставь свои инструменты.
- `impeccable` сначала просит выполнить `.agent/skills/impeccable/scripts/impeccable context` (на Windows —
  `impeccable.cmd`). Это самодостаточный бинарь, скачивается при первом запуске; Node не нужен. Выполни его один раз за сессию,
  из корня проекта, и следуй выводу. Если не скачался — скажи пользователю одной строкой и читай `PRODUCT.md`/`DESIGN.md`, если они есть.
- Нет скилла или команды — одна строка пользователю, работа продолжается.

## 3. Протокол allskill (кратко — полный в `.agent/skills/allskill/SKILL.md`)

Порядок: шаг 0 → 1 → 2 → 3 → 4 → 5 в **каждой** задаче.

1. Прочитать `SKILLS.md`, записать одной строкой: «Задача: <тип>. Скиллы: <список>».
2. Минимум скиллов по типу задачи:
   - **интерфейс лаунчера (egui)**: `impeccable` (режимы `clarify` — понятные подписи, `animate`, `polish`, `harden`) + один из
     `ui-ux-pro-max`, `web-interface-guidelines`, `taste-skill`. Тексты — `/tov`: короткие кнопки с глаголом
     («Добавить», «Удалить», «Установить»). Иконка без подписи у главного действия — ошибка;
   - **сайт `site/`**: минимум два из `impeccable`, `taste-skill`, `redesign-skill`, `ui-ux-pro-max`,
     `web-interface-guidelines`, `design-system`; тексты — `copywriting` + `/tov`; после правок `/ui-audit` и `/live`;
     идеи компонентов — 21st.dev и reactbits.dev, перенесённые в чистый HTML/CSS/JS;
   - **скорость** (загрузка, распаковка, удаление, FPS, память): `investigate-first`, сначала замер и причина, цифры «до/после»;
   - **новая функция**: `lean-build`; больше одного файла — сначала `/ecc-plan`;
   - **баг**: `investigate-first` → `surgical-patch`; **рефакторинг**: `safe-refactor`; **миграция**: `migration`;
   - **ввод/сеть/архивы/пути**: `ecc-security-review` (zip-slip, размеры); **новая чистая логика**: `/ecc-tdd`;
   - **поиск по коду**: `caveman-explore`/`cavecrew`; **ревью**: `caveman-review`/`/ecc-code-review`;
   - **видео**: `remotion-best-practices` + `remotion-create`/`remotion-render`.
3. Каждый скилл читается отдельно, не один «главный» вместо всех.
4. Инструменты: документация крейтов (context7 или поиск) перед незнакомым API egui/eframe/tokio/reqwest/zip; браузер для сайта.

**Запрещено:** `caveman-setup`, `-discover`, `-evidence-review`, `-manage`, `-optimize` (гонят запросы через сторонний шлюз Caveman Cloud),

Сжатие ответов по просьбе владельца («коротко») — `ultracave.md` рядом с allskill.

## 4. Проект

**Что это.** Minecraft-лаунчер на Rust (egui/eframe 0.37, glow, прозрачное безрамочное окно). Ставит ваниль и Forge, моды, шейдеры,
ресурспаки, карты, модпаки (Modrinth + CurseForge), хостит собственный Forge-сервер, умеет комнаты для друзей (UPnP), Pomme — нативный
Rust-клиент. Было «LLM Launcher Madrid», с 2026-11-17 называется **Sad Launcher**.

**Пути (Windows 11, Git Bash, Rust toolchain `x86_64-pc-windows-gnu`)**
- Проект: `D:\working WIN\LLM launcher` (бинарники `sad-launcher` и `installer` в `src/bin/`)
- Данные: `%APPDATA%\Sad Launcher\` (`config.json`, `game/`, `server/`, `runtime/{major}/`, `meta/`, `logs/`). Старая папка
  `LLM Launcher Madrid` переносится сама (`config::migrate_legacy`), пути внутри json переписываются.
- Установка: `%LOCALAPPDATA%\Programs\Sad Launcher\sad-launcher.exe`
- Репозиторий: `github.com/simsislam89-crypto/sad-launcher`, приватный, ветка `main`. Коммиты только по просьбе владельца.
- Сайт: `site/` (статика), запуск локально — `Запустить сайт.bat` (порт 8080). Домена пока нет.

**Архитектура `src/`** (подробно — раздел «Архитектура» в `RRR.md`)
`main.rs` (single-instance, bootstrap сервера, `window_icon`) · `config.rs` (serde(default), `APP_DIR`, `APP_TITLE`, `VERSION`, `SITE_URL`,
миграция) · `app.rs` (всё состояние, задачи через mpsc + AtomicBool cancel, карточка удаления, окно «О лаунчере», нижняя панель) ·
`minecraft.rs` · `server.rs` · `launch.rs` · `mods.rs` (поиск/установка модов и модпаков) · `unpack.rs` (параллельная распаковка zip) ·
`remove.rs` (фоновое удаление) · `profiles.rs` (сборки-экземпляры) · `java.rs` · `loader.rs` · `net.rs` (общий tokio-рантайм, загрузчик с докачкой) ·
`deps.rs`, `packinfo.rs`, `smart.rs`, `categories.rs`, `ftb.rs` · `room.rs`, `upnp.rs` · `pomme.rs` · `platform.rs` (обёртки под Linux/macOS) ·
`theme.rs`, `widgets.rs`, `icons.rs`, `shared.rs`, `util.rs` · `views/` (play, versions, build, mods, server, settings) ·
`bin/installer.rs` (установщик с `include_bytes` из `assets/launcher-payload.exe`).

## 5. Что сделано в 0.7.0 и почему так (держать в голове)

- **Переименование.** Идентификаторы `MADRID_*`, мьютекс `LLMLauncherMadrid-Instance`, topic комнат `llmmadrid-*` НЕ переименованы
  специально — иначе сломается совместимость с уже запущенными копиями и друзьями. Менять только по прямому решению владельца.
- **Скорость паков (`unpack.rs`, `mods.rs`).** Архив не распаковывается во временную папку и не копируется второй раз: индекс читается
  прямо из zip, `overrides` пишутся в сборку в 2–8 потоков (у каждого потока свой `ZipArchive`, крупные файлы первыми, каталоги
  созданы заранее) параллельно со скачиванием модов. Файлы, перекрытые overrides, не качаются. `LocalFiles`: мод с тем же именем,
  размером и SHA-1 из другой сборки берётся хардлинком (запасной вариант — копия). CurseForge: имена и размеры одним
  `POST /mods/files` через зеркало `api.curse.tools`. Замер: Additive (51 МБ) за 4,4 с, дальше упор в сеть (~12 МБ/с); распаковка
  overrides занимает миллисекунды. Семафор скачиваний — 32.
- **Удаление (`remove.rs`).** `queue(title, path)` мгновенно переименовывает папку в `data/.trash` (тот же диск), сборка сразу исчезает
  из списков, потом поток удаляет файлы в 2–8 потоков, снимая read-only. `queue_files` — пачка файлов (удалить все моды).
  `sweep_leftovers()` при старте добирает недоделанное. Карточка прогресса справа снизу: масштаб 0,92→1, после «Удалено» держится
  ~1,8 с и сжимается. **Никогда не вызывай `remove_dir_all` из потока интерфейса.**
- **UI.** «+» на карточках каталога → «Добавить»/«Скачать»/«Установить» с подсказками; в строках модов «×» → «Удалить»/«Точно?».
  `paint_status_dot` рисует точку в своём rect (старый `status_dot` занимал место и уезжал на строку ниже). Масштаб карточек:
  появление с 96 %, +1,5 % при наведении, −1 % при нажатии (через `TSTransform` и `ctx.set_transform_layer`).
- **Бренд.** Иконка — одна белая «S» на чёрном скруглённом квадрате (`assets/icon.png|ico`). В шапке лаунчера логотипа нет, только текст
  «SAD LAUNCHER · MINECRAFT · v…». Установщик — тоже без логотипа.
- **Окно «О лаунчере»** (кнопка слева снизу рядом с версией): ссылки «Открыть» на данные/игру/журналы, строки сборка/Java/каталоги/
  загрузчики, три совета, кнопка «Сайт лаунчера». `config::SITE_URL` пока пустая строка, кнопка неактивна. Когда владелец назовёт
  домен — вписать его и пересобрать.
- **Сайт.** Без библиотек. Воксельный рельеф на canvas (низкое разрешение, ~20 fps, пауза вне экрана), прокрутка-контейнер на
  `animation-timeline: view()`, spotlight-карточки, магнитная кнопка, одна бегущая строка. Класс `.lite` для слабых устройств
  (≤4 ядра, ≤4 ГБ, save-data) отключает blur и тяжёлую анимацию; учтены `prefers-reduced-motion` и `prefers-reduced-transparency`.
  Скачивание: Windows → `download/SadLauncherSetup.exe` (его кладёт `make-dist.sh`), Linux/macOS — раскрывающаяся инструкция сборки
  из исходников. Для работы этой инструкции репозиторий должен быть публичным — вопрос открыт, решает владелец.
- **Порт Linux/macOS.** WinAPI за `cfg(windows)`, остальное через `platform.rs`. `cargo check` под Linux и macOS проходит,
  **живого запуска на этих системах не было.**
- **Хостинг сайта.** `netlify.toml` (publish=`site`), `vercel.json`, GitHub Pages — только ручной запуск (на бесплатном плане нужен публичный репо).

## 6. Грабли (не наступать)

Полный список — в `RRR.md`. Самые дорогие:

1. **windres ломается от пробелов в пути.** Иконку в exe встраивает `build.rs` через копию в `%TEMP%`. Крейт `winresource` не использовать.
2. **BOM в config.json** ломает serde, лаунчер тихо грузит дефолты. Конфиг править Python-ом (utf-8 без BOM), не `Set-Content`.
3. **Слайдер** без `resp.mark_changed()` не сообщает об изменении.
4. **`win_args.txt` Forge-сервера** — токенизировать по пробелам.
5. **`JavaEvent::Done` нужно эмитить всегда**, иначе интерфейс считает загрузку проваленной.
6. **Сканирование папок в интерфейсе** — только через кэш (`dir_size` каждый кадр = лаги).
7. **Facets Modrinth:** `categories:{loader}` только для `mod`; для shader/resourcepack/modpack — только `project_type` + `versions`.
8. **CurseForge без ключа:** поиск идёт через зеркало, скачивание — публичный CDN. Карты только из CF.
9. **Python-патчи на Windows** переписывают файл с CRLF (текстовый режим). Одноразовые скрипты открывай с `newline=''`.
10. **Кириллица в именах файлов** в Git Bash выглядит кракозябрами, файл при этом корректен (проверяй через PowerShell).
11. `mv` в скриптах сборки → `cp -f`.
12. **Не запускай собранный exe без `MADRID_SECOND_INSTANCE=1`.** Иначе новая копия мигрирует данные владельца, перепишет ярлыки и
    автозапуск. Режим «dev copy» их не трогает.
13. Консольные окна — только с `CREATE_NO_WINDOW` (0x08000000).

**Переменные для разработки**
- `MADRID_SECOND_INSTANCE=1` — запустить копию рядом с рабочей (без миграции, ярлыков, автозапуска).
- `MADRID_DEV_TAB=play|versions|build|mods|modpacks|server|settings` — открыть нужную вкладку.
- `MADRID_DEV_ABOUT=1` — открыть окно «О лаунчере».
- `MADRID_PACK=<id>` — для живого теста скорости паков (`live_pack_speed`, `--ignored`).

**Команды**
```bash
cargo check                                  # без ошибок и без новых предупреждений
cargo test                                   # сейчас 57 проходят, 9 живых игнорируются
cargo test live_ -- --ignored                # живые тесты, только по задаче
bash scripts/make-dist.sh                    # Sad Launcher.exe + установщик + site/download/SadLauncherSetup.exe
```
Скриншот окна: PowerShell + `PrintWindow` по `MainWindowHandle` (сначала `ShowWindow(9)` и `SetForegroundWindow`; ждать, пока окно
вырастет из 6×6). Не делай скриншоты с кликами, пока владелец играет в fullscreen.

## 7. Проверка перед словом «готово»

1. `cargo check` — ноль ошибок и ноль новых предупреждений; затем `cargo test`.
2. `bash scripts/make-dist.sh`.
3. UI лаунчера: скриншот затронутой вкладки; проверь наложения, обрезку текста, анимацию.
4. Сайт: `Запустить сайт.bat`, ширины 375 и 1440 px, консоль без ошибок.
5. **Всегда** дописать `RRR.md` разделом «Обновление <дата>».
6. `verify-and-stop`. Без него нельзя писать «готово», «работает», «исправлено».
7. **Всегда** после завершения задачи и проверок сделать `git commit` и `git push` в `main` (секреты не коммитить).

## 8. Вкусы и правила общения с владельцем

- Всё на русском. Чёрно-белый минимализм, прозрачные «стеклянные» элементы, без цветных акцентов.
- Много кликабельности и понятных подписей: главное действие подписано словом, не только иконкой.
- Живой прогресс (моды «пролетают» списком), без зависаний: тяжёлое — в фоне, интерфейс всегда отвечает.
- Минимум файлов на диске. Ничего не запускается и не подключается без явного действия пользователя.
- Владелец пишет коротко и по-разговорному, без технических деталей. Не переспрашивай очевидное — выбирай разумный вариант и
  сообщи одной строкой. Не пиши вступлений. Говори прямо, что проверено, а что нет.
- Владелец не любит потерю данных. **17.11.2026 папку проекта стёрли целиком**, а `src/` ни разу не коммитился. Исходники пришлось
  восстанавливать из логов сессий (результат совпадает по сборке и 57 тестам, но сверить с оригиналом уже нельзя). Вывод: после каждой
  значимой порции работы предложи закоммитить и запушить `src/` в приватный репозиторий. Коммит делай только после «да».
- Личные данные владельца (почта, имя, пути профиля) не отправляй во внешние сервисы. Для git используется адрес GitHub noreply.
- Никогда не трогай и не удаляй `%APPDATA%\Sad Launcher`, `D:\working WIN\LLM launcher` и чужие проекты рядом.

2. Открой `site/index.html` через `Запустить сайт.bat`: страница грузится, консоль пуста.
